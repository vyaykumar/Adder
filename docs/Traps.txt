A few critical implementation traps hidden in your specification—along with how you frame the narrative of this repository—will make the difference between a project that merely compiles and one that gets you fast-tracked in systems interviews.
1. The Hidden Implementation Traps in the Spec
 * The P-Core / E-Core Trap on Your CPU: The specification lists a 12th Gen Intel Core i3-1220P, which mixes performance (P) and efficiency (E) cores. That specific chip only has 2 P-cores and 8 E-cores. Because the specification requires running N=4 clean nodes pinned to cores of the same type so mixed cores don't create stragglers on their own, you must pin your 4-node tests to the E-cores, not the P-cores. If you put 2 nodes on P-cores and 2 on E-cores, your baseline will have a permanent 2x hardware straggler before you even inject a synthetic delay.
 * The RNR (Receiver Not Ready) Death Spiral: The specification mentions building a "credit loop" in ring.h/.cc using shared/ring_buffer.h. Do not skip flow control. In RDMA, if Node A posts an IBV_WR_SEND before Node B has posted a matching ibv_post_recv, the Queue Pair throws an RNR NAK (Receiver Not Ready), stalls in a hardware retry timer, and destroys your P99.9 tail latency. Set min_rnr_timer carefully during the RTR transition, and never send a chunk without a credit confirming the receiver buffer is posted.
 * The 40-Byte UD Offset Bug: For Unreliable Datagram (UD), the specification mandates leaving 40 extra bytes at the start of each receive buffer for the Global Routing Header (GRH). A classic libibverbs bug is allocating a 1024-byte buffer for a 1024-byte MTU message; the NIC writes 40 bytes of GRH plus 1024 bytes of payload, overflowing the buffer and failing with IBV_WC_LOC_LEN_ERR. Your registered receive buffer must be MTU + 40 bytes, and your data pointer starts at buf + 40.
 * Floating-Point Non-Associativity: The success criteria note that ring all-reduce must be bit-exact on integer data, while floating-point data only matches within a tolerance because the sum order changes float results. In interviews with AI systems engineers, bring this up proactively: explain how your Ring (a+b)+c+d vs. Binary Tree (a+b)+(c+d) topologies produce slightly different IEEE-754 rounding errors, which is a major real-world headache for deterministic LLM reproducibility.
